# ROADMAP.md

## Реализовано в текущем MVP

### Базовый интерфейс

- Современные фильтры.
- Полная карточка фильма.
- КП / IMDb / личная оценка.
- Добавление и удаление фильмов.
- Светлая / тёмная / системная тема.
- Современный экран жанров.
- Контекстная навигация карточки.
- Закреплённая кнопка «Назад» при прокрутке.

### Импорт и данные

- Импорт публичного списка Кинопоиска.
- Общий каталог Cloudflare D1.
- Серверный кэш карточек фильмов.
- Поиск по общему каталогу.
- Быстрый выбор в пустом состоянии Каталога.
- Блок «Можно начать с этого».
- Добавление найденного фильма в личную кинотеку.
- Минимальные записи `library_migration` автоматически обогащаются при первом открытии карточки.
- Добавлен защищённый пакетный endpoint `/api/catalog-enrich` для постепенного обогащения каталога небольшими порциями без повторных запросов к уже готовым карточкам.
- Ежедневная автоматика GitHub Actions включена и проверена реальным scheduled-run в Production.

### Личная кинотека

- Таблицы `users` и `user_movies`.
- Серверное хранение личной кинотеки.
- Миграция реальной кинотеки на сервер — 1098 позиций.
- Серверная синхронизация статусов «Хочу посмотреть», «На вечер», «Просмотрено» и личной оценки.
- `localStorage` оставлен как cache/fallback.
- Исправлена обработка неизвестного рейтинга: `NULL`, а не `0`.
- Убран скрытый фильтр КП от 6 по умолчанию в «Мои фильмы».
- Тестовые seed-фильмы отделены от реальной кинотеки.

## Текущая техническая задача — довести каталог до полной тестовой выборки

Перед переходом к Telegram Mini App нужно закончить бесплатное постепенное обогащение оставшихся `library_migration` записей.

Историческая контрольная точка после queue-safe Preview-теста: 294 полноценно обогащённые карточки и 804 `library_migration` записи из 1098. После неё очередь продолжает уменьшаться автоматически, поэтому эту цифру не считать текущим живым остатком.

Правила:

- использовать текущий лимит ПоискКино API;
- не запрашивать повторно уже обогащённые фильмы;
- обогащать небольшими контролируемыми порциями;
- пакетный endpoint защищать секретом `CATALOG_ENRICH_KEY`;
- временная ошибка отдельного фильма не должна блокировать очередь — запись переносится в конец очереди;
- явная ошибка конкретного фильма (`404/410/422`) выводится из фоновой очереди в `library_migration_failed`;
- `library_migration_failed` остаётся доступным для повторной попытки при ручном открытии карточки;
- ошибки авторизации, тарифа и лимита поставщика (`401/402/403/429`) должны останавливать текущую партию;
- queue-safe успешный сценарий проверен на Preview: `requested=1`, `attempted=1`, `enriched=1`, `failed=0`, `stopped=false`;
- ежедневная автоматика реализована через GitHub Actions: максимум 6 партий × 25 фильмов = 150 попыток в сутки;
- запуск по расписанию — один раз в сутки;
- ручной `workflow_dispatch` безопасен по умолчанию: 1 партия × 1 фильм; размер партии и число партий можно увеличить только явным выбором перед ручным запуском;
- Production `CATALOG_ENRICH_KEY` и GitHub repository secret синхронизированы;
- ручной Production-тест workflow успешно выполнен: `attempted=1`, `enriched=1`, `failed=0`;
- первый самостоятельный scheduled-run успешно выполнен в Production: `attempted=150`, `enriched=150`, `failed=0`;
- workflow использует только защищённый Production endpoint и repository secret `CATALOG_ENRICH_KEY`; сам ключ не хранится в репозитории;
- GitHub Actions schedule не считать гарантией запуска минута-в-минуту: для фонового наполнения важен ежедневный запуск, а не точное время старта.

Когда очередь `library_migration` закончится, перед переходом к Telegram провести финальный аудит каталога: проверить остаток очереди, количество `library_migration_failed`, полноту ключевых полей и сохранность всех 1098 связей `user_movies`.

## Принцип приоритизации

> Помогает ли она пользователю быстрее выбрать фильм сегодня?

Если нет — переносится на более поздний этап.

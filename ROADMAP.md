# ROADMAP.md

## Реализовано в текущем MVP

### Базовый интерфейс

- Современные фильтры.
- Полная карточка фильма.
- КП / IMDb / личная оценка.
- Добавление и удаление фильмов.
- Светлая / тёмная / системная тема.
- Современный экран жанров.
- Контекстная навигация карточки.
- Закреплённая кнопка «Назад» при прокрутке.

### Импорт и данные

- Импорт публичного списка Кинопоиска.
- Общий каталог Cloudflare D1.
- Серверный кэш карточек фильмов.
- Поиск по общему каталогу.
- Быстрый выбор в пустом состоянии Каталога.
- Блок «Можно начать с этого».
- Добавление найденного фильма в личную кинотеку.
- Минимальные записи `library_migration` автоматически обогащаются при первом открытии карточки.
- Добавлен защищённый пакетный endpoint `/api/catalog-enrich` для постепенного обогащения каталога небольшими порциями без повторных запросов к уже готовым карточкам.
- Ежедневная автоматика GitHub Actions включена и проверена реальными scheduled-run в Production.
- Workflow не останавливает весь scheduled-run из-за транспортного таймаута `curl` с кодом 28 и продолжает следующие партии.

### Личная кинотека

- Таблицы `users` и `user_movies`.
- Серверное хранение личной кинотеки.
- Миграция реальной кинотеки на сервер — 1098 позиций.
- Серверная синхронизация статусов «Хочу посмотреть», «На вечер», «Просмотрено» и личной оценки.
- `localStorage` оставлен как cache/fallback.
- Исправлена обработка неизвестного рейтинга: `NULL`, а не `0`.
- Убран скрытый фильтр КП от 6 по умолчанию в «Мои фильмы».
- Тестовые seed-фильмы отделены от реальной кинотеки.
- Telegram identity подключена к личной кинотеке через серверную сессию.
- Текущая библиотека из 1098 позиций безопасно скопирована с `local_test_user` на подтверждённого владельца Telegram; исходные записи сохранены как резерв.
- Проверена запись пользовательского состояния под Telegram identity: «На вечер» сохраняется после закрытия и повторного открытия Mini App.
- Проверена независимость библиотек двух разных Telegram-пользователей.
- Проверено, что один Telegram-пользователь получает одну и ту же библиотеку на разных устройствах.
- BotFather Menu Button настроен на Production `/telegram-entry.html`.
- Одноразовый серверный `/api/legacy-library-claim` удалён после успешного Production-перехода.

## Фоновое обогащение каталога

Обогащение оставшихся `library_migration` записей продолжается автоматически и **не блокирует дальнейшее развитие Telegram Mini App**.

Историческая контрольная точка после queue-safe Preview-теста: 294 полноценно обогащённые карточки и 804 `library_migration` записи из 1098. После неё очередь продолжает уменьшаться автоматически, поэтому эту цифру не считать текущим живым остатком.

Последняя подтверждённая Production-контрольная точка после первой партии scheduled-run #9: `pendingAfter=328`. В этой партии было `attempted=25`, `enriched=24`, `failed=1`, `retryLater=1`. Следующая партия получила транспортный timeout; после этого workflow усилен так, чтобы timeout `curl` с кодом 28 не останавливал оставшиеся партии.

Правила:

- использовать текущий лимит ПоискКино API;
- не запрашивать повторно уже обогащённые фильмы;
- обогащать небольшими контролируемыми порциями;
- пакетный endpoint защищать секретом `CATALOG_ENRICH_KEY`;
- временная ошибка отдельного фильма не должна блокировать очередь — запись переносится в конец очереди;
- явная ошибка конкретного фильма (`404/410/422`) выводится из фоновой очереди в `library_migration_failed`;
- `library_migration_failed` остаётся доступным для повторной попытки при ручном открытии карточки;
- ошибки авторизации, тарифа и лимита поставщика (`401/402/403/429`) должны останавливать текущую партию;
- queue-safe успешный сценарий проверен на Preview: `requested=1`, `attempted=1`, `enriched=1`, `failed=0`, `stopped=false`;
- ежедневная автоматика реализована через GitHub Actions: максимум 6 партий × 25 фильмов = 150 попыток в сутки;
- запуск по расписанию — один раз в сутки;
- ручной `workflow_dispatch` безопасен по умолчанию: 1 партия × 1 фильм; размер партии и число партий можно увеличить только явным выбором перед ручным запуском;
- Production `CATALOG_ENRICH_KEY` и GitHub repository secret синхронизированы;
- ручной Production-тест workflow успешно выполнен: `attempted=1`, `enriched=1`, `failed=0`;
- первый самостоятельный scheduled-run успешно выполнен в Production: `attempted=150`, `enriched=150`, `failed=0`;
- транспортный timeout `curl` с кодом 28 теперь фиксируется отдельно и не завершает весь scheduled-run;
- другие транспортные ошибки и HTTP non-200 по-прежнему завершают job с диагностикой;
- workflow использует только защищённый Production endpoint и repository secret `CATALOG_ENRICH_KEY`; сам ключ не хранится в репозитории;
- GitHub Actions schedule не считать гарантией запуска минута-в-минуту: для фонового наполнения важен ежедневный запуск, а не точное время старта.

Когда очередь `library_migration` закончится, провести финальный аудит каталога: проверить остаток очереди, количество `library_migration_failed`, полноту ключевых полей и сохранность всех связей `user_movies`. Этот аудит выполняется параллельно и не является блокером Telegram-разработки.

## Telegram Mini App — Production-этап закрыт

Цель этапа достигнута: реальные пользователи Telegram получают независимые личные кинотеки при общем каталоге `movies`.

Реализовано и проверено в Production:

1. Серверная проверка Telegram `initData`.
2. Создание/обновление Telegram-пользователя в существующей таблице `users`.
3. Входная страница `telegram-entry.html` с Telegram Web App SDK.
4. Создание подписанной `HttpOnly; Secure; SameSite=Lax` серверной сессии после проверки `initData`.
5. `/api/user-library` работает только с подтверждённой Telegram-сессией и не использует `local_test_user` как resolver.
6. При смене Telegram-пользователя локальный пользовательский cache очищается, чтобы не смешивать библиотеки.
7. BotFather / Menu Button настроен на Production `/telegram-entry.html`.
8. Старая библиотека из 1098 позиций перенесена подтверждённому владельцу.
9. Под Telegram identity прочитаны все 1098 перенесённых фильмов.
10. Изменение статуса «На вечер» записывается на сервер и сохраняется после повторного открытия Mini App.
11. Два разных Telegram-пользователя получают независимые кинотеки; изменение второго пользователя не затрагивает первого.
12. Один Telegram-пользователь видит ту же библиотеку на другом устройстве.
13. Одноразовый серверный legacy endpoint удалён после Production-аудита.

Резервные записи `local_test_user` пока не удаляются. Решение об их окончательном удалении принимается отдельно после необходимости в резерве.

Frontend-маркер старой localStorage → server миграции пока сохраняется для совместимости, потому что текущий импорт использует его как признак активной серверной синхронизации. Его удаление — отдельная небольшая техническая задача после отвязки от сценария импорта.

Уже заложенная архитектура сохраняется:

- `movies` — общий каталог для всех;
- `users` — реальные пользователи;
- `user_movies` — личное состояние каждого пользователя;
- данные фильма не дублируются для каждого пользователя;
- уже обогащённая карточка фильма повторно не запрашивается у внешнего поставщика только потому, что её добавил другой пользователь.

## Следующий продуктовый этап

После закрытия Telegram identity приоритет возвращается к основной гипотезе продукта: сократить время выбора фильма.

### Улучшение выбора

- Более быстрый сценарий «Помоги выбрать» без обязательного AI.
- Улучшение быстрых фильтров и пресетов.
- Фильтры по стране и десятилетию.
- Естественные комбинации вроде «американские комедии 90-х».
- Улучшение качества рекомендаций из собственной кинотеки.
- Улучшение явности действия «Хочу посмотреть» в карточке фильма: иконка без текста сейчас недостаточно очевидна и требует отдельного UX-решения.

### Совместный выбор — версия 2

Не включать в текущий MVP.

- Приглашение друзей / семьи.

- Tinder/турнир: попарное сравнение или свайпами до победителя.

## Принцип приоритизации

Любая новая функция оценивается по вопросу:

> Помогает ли она пользователю быстрее выбрать фильм сегодня?

Если нет — переносится на более поздний этап.

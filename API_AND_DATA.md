## 3. Пользовательская кинотека

Связь пользователя с фильмом хранится отдельно.

```json
{
  "id": "string",
  "user_id": "string",
  "media_item_id": "string",
  "status": "none|watchlist|watched|rewatch",
  "for_tonight": true,
  "personal_rating": 8,
  "watched_at": "datetime|null",
  "added_at": "datetime|null",
  "selected_for_tonight_at": "datetime|null",
  "note": "string|null",
  "source_note": "string|null",
  "created_at": "datetime",
  "updated_at": "datetime"
}
```

### Значения статуса

#### `none`
Фильм не находится в кинотеке пользователя.

#### `watchlist`
Фильм находится в списке «Хочу посмотреть».


#### `watched`
Фильм просмотрен.

#### `rewatch`
Фильм просмотрен ранее, но добавлен в список для повторного просмотра.

---

## 4. Правила жизненного цикла фильма

Основной сценарий:

```text
none
→ watchlist
→ watched
```

Дополнительные переходы:

```text
watchlist → none
watched → rewatch
rewatch → watchlist
```

### Важное правило
«На вечер» не является статусом. Это независимый флаг `for_tonight`, который может быть включён у фильма в «Хочу посмотреть». При переводе фильма в `watched` флаг `for_tonight` автоматически сбрасывается.

Приложение никогда не считает фильм просмотренным автоматически.

Статус `watched` устанавливается только после явного действия пользователя.

## 5. Рейтинги

В приложении существуют разные типы оценок.

### Внешние рейтинги
- Кинопоиск;
- IMDb;
- TMDb — на будущее.

### Личная оценка пользователя
Хранится отдельно:

```json
{
  "personal_rating": 8
}
```

Шкала:
- целое число от 1 до 10;
- можно изменить после сохранения;
- отображается отдельно от КП и IMDb.

### Интерфейс

```text
КП 7.4
IMDb 7.1
Моя оценка 8/10
```

Нельзя использовать просто слово «Рейтинг» без указания источника.

---

## 6. Фильтры

Структура фильтров:

```json
{
  "type": "all|film|series|mini_series",
  "genres": ["Ужасы", "Триллер"],
  "min_kinopoisk_rating": 6.0,
  "year_from": 2020,
  "year_to": 2026,
  "availability": ["kinopoisk"],
  "status": "watchlist"
}
```

### Правила
- минимальный рейтинг Кинопоиска по умолчанию: `6.0`;
- жанров может быть несколько;
- год можно задавать:
  - готовым пресетом;
  - точным диапазоном;
- фильтры применяются только к кинотеке пользователя;
- пустые фильтры не должны визуально перегружать интерфейс.

## 7. Добавление фильма

### 7.1. По названию
Пользователь вводит название.

Система:
1. выполняет поиск;
2. показывает найденные варианты;
3. пользователь выбирает нужный;
4. нажимает «Добавить в Хочу посмотреть».

### 7.2. По ссылке
Поддерживаемые источники на первом этапе:
- Кинопоиск;
- IMDb — позже;
- YouTube;
- онлайн-кинотеатры;
- другие внешние страницы.

Система должна:
1. определить источник;
2. извлечь идентификатор или название;
3. найти фильм в базе;
4. показать карточку подтверждения;
5. добавить в кинотеку.

---

## 8. Импорт из Кинопоиска

Цель:
импортировать список пользователя «Буду смотреть».

### Возможные варианты реализации
1. официальный экспорт, если он доступен;
2. импорт пользовательского файла;
3. импорт публичной страницы;
4. сторонний API;
5. расширение браузера — позже.

### Ограничения
- не использовать неофициальный источник без проверки лицензии и стабильности;
- не хранить логин и пароль Кинопоиска;
- не автоматизировать вход в аккаунт пользователя без отдельной безопасной архитектуры;
- учитывать возможные ограничения и блокировки.

---

## 9. Источник данных

Для MVP возможны три режима.

### Режим A. Локальные тестовые данные
Используется сейчас.

Плюсы:
- быстро;
- не нужен сервер;
- удобно тестировать UX.

Минусы:
- данные не сохраняются между устройствами;
- нельзя импортировать реальные списки.

### Режим B. Внешний API
Возможные данные:
- название;
- год;
- жанры;
- постер;
- описание;
- рейтинги;
- ссылки.

Перед выбором API проверить:
- лицензию;
- лимиты;
- стоимость;
- стабильность;
- возможность коммерческого использования.

### Режим C. Собственная база
Предпочтительный вариант после MVP.

## 12. Совместный выбор

### Основной принцип
Приложение ищет пересечение интересов участников.

### Возможные источники кандидатов
- фильмы, которые все хотят посмотреть;
- фильмы, которые никто не смотрел;
- фильмы с высоким средним рейтингом;
- фильмы, подходящие под общие фильтры.

### На будущее
Режим по типу Tinder/турнира:
- попарное сравнение;
- свайпы;
- финальный победитель.

В MVP не включать.

## 13. Telegram Mini App

Для настоящего Mini App потребуется:

- Telegram Bot;
- HTTPS-домен;
- Telegram WebApp SDK;
- получение Telegram user data;
- серверная проверка `initData`;
- backend;
- база данных.

### Минимальные шаги
1. создать Telegram-бота;
2. настроить кнопку открытия Mini App;
3. подключить опубликованный сайт;
4. реализовать авторизацию через Telegram;
5. перенести локальное состояние на сервер.

---

## 14. Безопасность

- Не доверять данным клиента.
- Проверять Telegram `initData` на сервере.
- Не хранить внешние пароли.
- Не отдавать секретные API-ключи в `index.html`.
- Все внешние API вызывать через backend.
- Ограничить частоту запросов.
- Валидировать ссылки.
- Защитить удаление и изменение данных авторизацией.

---

## 15. Что пока не реализовано

- backend;
- база данных;
- настоящая авторизация;
- сохранение между устройствами;
- настоящий импорт Кинопоиска;
- реальные постеры;
- реальные баннеры;
- стабильные внешние ссылки;
- групповой выбор;
- AI-подбор.

---

## 16. Текущий прототип

Текущий `index.html`:
- работает полностью на клиенте;
- использует тестовый массив фильмов;
- хранит состояние только до обновления страницы;
- предназначен для проверки UX;
- не является готовым production-приложением.

---

## 17. Правила для следующего чата

При продолжении разработки:
1. не менять утверждённую модель статусов без веской причины;
2. внешние и личные рейтинги хранить отдельно;
3. не хранить секреты в клиентском коде;
4. все реальные интеграции вести через backend;
5. сохранять один основной `index.html`;
6. любые новые поля сначала добавлять в эту спецификацию;
7. MVP не перегружать функционалом версии 2.

## 18. Реализованный общий каталог D1 — 2026-08-07

### Поиск

```text
GET /api/catalog-search?q={название}&limit=30
```

Правила:
- минимум 2 символа;
- поиск по русскому и оригинальному названию;
- выдача не более 30 результатов в MVP;
- frontend получает внутреннюю нормализованную модель;
- пустой запрос не возвращает общую ленту.

### Получение и обогащение карточек

```text
POST /api/movie-details
```

Порядок:
1. проверить D1 по `kinopoisk_id`;
2. вернуть найденные карточки;
3. запросить у поставщика только отсутствующие;
4. нормализовать;
5. сохранить в D1;
6. вернуть единый массив frontend-у.
